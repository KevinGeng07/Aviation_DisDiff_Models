Resuming once the jobs have stopped

Each run saves model/last.pt at the end of every epoch. A resumed job continues from there, so at most one partial epoch is lost.

When all the jobs have left the queue, whether they finished, hit the time limit or failed, resubmit only the runs that haven't reached 100
epochs:
cd /global/scratch/users/kevingeng/aviation-bayen/Aviation_DisDiff_Models
for d in finished_ckpt/2_architecture/distill_*; do
name=$(basename $d)
done_ep=$(tail -1 $d/model/metrics.csv 2>/dev/null | cut -d, -f1)
if [ "${done_ep:-0}" -lt 100 ] && ! squeue -h -u $USER -n $name | grep -q .; then
    L=$(echo $name | cut -d_ -f2); W=$(echo $name | cut -d_ -f3)
    bash savio/submit_distill_run.sh --name $name --student configs/students/swi_dit_${L}L_${W}.json \
        --save_dir $d --resume
fi
done
What this does for each run:
- Finished (100 epochs): skipped, so it doesn't sit in the queue just to exit.
- Still queued or running: skipped.
- Stopped early: resubmitted with --resume. It continues from its last.pt, writing to the same folder, with its new log in the same logs/
folder.
- No metrics.csv yet (failed before finishing an epoch): resubmitted, and it starts from scratch.

Run the loop again after each round of jobs until every run shows 100/100. It's safe to repeat.

To resume a single run:
bash savio/submit_distill_run.sh --name distill_4_256 --student configs/students/swi_dit_4L_256.json \
    --save_dir finished_ckpt/2_architecture/distill_4_256 --resume

To train past 100 epochs: add --epochs 150 to the resume command. The learning-rate schedule was set for 100 epochs, so the extra epochs
run at the schedule's final learning rate rather than restarting it.

When all 7 are done, compare them:
SCRIPT=benchmark EVAL_ARGS="--out results/stage2.json" sbatch savio/job_eval.sh finished_ckpt/2_architecture
